# Luros 1.0.4 增量融合验收

## 功能范围

- 同一服务商最多九个账号；首账号沿用旧凭据，附加账号使用规范的 `#2` 至 `#9` 标识。
- 模型选择、默认辅助模型、待发送消息及派生会话携带账号身份，不保存密钥。
- 模型页进入时拉取列表，手动刷新显示原位进度；保留本地备注与模型能力设置。
- 模型选择器增加独立用量入口；输入框原有余额胶囊和原余额详情继续保留。
- 新额度入口支持 `https://100milionseek.top/v1` 的代币响应头；其他中转保留探测流程。
- 货币金额显示两位小数，代币、百分比与用量窗口各自格式化。查询失败保留最近有效数字和成功时间，状态仍提示无法查询。
- 退出先使账号代次失效，阻止迟到登录、验证及刷新恢复凭据；共享密钥池仅在最后一个账号离开时清理。
- 被动响应头通过持久 UUID 代次及文件锁跨工作进程检查，旧观察器不能重建已清除额度池。
- 新文案使用独立 `Quota` 字符串表：50 条键，每条十三种语言。原字符串表与实时活动资源不变。

## 已执行的静态检查

- 无障碍标签可达性检查。
- 持久化读取检查、递归删除变量保护检查、Objective-C 数据桥接检查。
- 三份字符串目录的语言完整性；新额度表的重复键、十三语言及非空翻译检查。
- 三份字符串目录的格式占位符检查。

这些检查不证明 Swift 类型检查、资源打包或真机行为通过。

## 额度只读入口与更新恢复修正

只读核对发现：更新中断的压缩在服务端已有取消回执，本地会话历史却缺少该回执；后续普通轮次已结束，本地仍保留压缩状态。未修改设备上已有会话记录。

源码修正：模型选择器额度页不再带账号管理，设置入口继续保留管理；回放按已显示的结束回执计数，保留恢复新补的取消/结束回执；旧版部分回放仅重读边界，不删除历史。宿主确认任务终止时清理运行和压缩两种标记，普通轮次结束及新提问也清理遗留压缩状态。

自动压缩的最近占用快照保存在会话头，先落盘再请求；对账完成前不自动触发，保存或打开会话期间的停止可使未启动请求失效。手动压缩和已有服务商轮数上限恢复保持原路径。

回归新增在 `Tests/ChatTranscript/ReplayEndCheck.swift` 与 `Tests/ChatTranscript/main.swift`，包括取消回执重放、旧部分回放升级、真实压缩仍活跃、双状态终态收尾、快照往返及仅读头恢复。同时修正后者三处无效的双反斜杠键路径，保留原断言。

已通过：七个改动 Swift 文件的旧前端兼容副本语法解析（仅移除既有尾逗号并降级一处既有 if 表达式）、无障碍标签可达性、持久化读取、消息配对与差异空白检查。原生完整源码不能由本机旧前端直接解析；未进行 Swift 类型检查、编译或执行上述回归，`make check` 仍因缺少 `xcodebuild` 阻塞。

## 原余额入口统一新线路与有效数据持久化

输入框余额胶囊、原余额卡片、设置账号列表与独立额度详情改为同一数据源，统一复用已有的 `https://100milionseek.top/v1` 专用代币适配。不再从客户端调用旧余额接口；胶囊外观和卡片结构保留。货币仍为两位小数，tokens保留原精度并在胶囊紧凑显示，其他原始额度及窗口剩余比例保留单位标记。

客户端保存脱敏额度快照和服务商/账号存储ID/额度池绑定，不保存凭据、完整配置、原始响应、错误正文或账单链接。重启先恢复最近数据；查询异常、空返回或晚到的旧快照不改写最近有效数字及其成功时间。自动查询尝试时间仅作限频，不用于显示更新时间。失败卡片仍显示上次更新时间，账号列表保留数字并标注“上次数据”。

完整账号列表用于撤销退出/换池绑定；查询前后均核对绑定并检查客户端代次。修改配置成功先作废等待中的旧请求，再由完整账号列表确认是否换池，同池重新登录保留原有效数据；退出成功立即撤销对应绑定。登录取消或失败不删除余额。经精确池标识确认共用凭据的账号同步该池数字，退出其中一个不删除其他绑定，其他额度池不借用数字。

新增回归源码：

- `AgentQuotaDisplayTests`：金额与原始单位精度、零值、失败/空值保值与时间、错误响应携带数字、旧回包、账号池匹配、窗口剩余比例及序列化往返。
- `Tests/QuotaDisplay/ProviderBalanceStoreCheck.swift`：直接编译生产存储，注入假传输和独立临时目录，验证仅调用新线路、多账号隔离、同池同步、重启恢复、空值/网络失败、退出/换池期间晚回包、单条损坏槽位保留、整文件隔离及不可读文件禁止覆盖；已接入现有harness脚本。
