# 用量累计账本验收

## 记录口径

- 设置「用量统计」与聊天页「会话用量」读取同一个 SQLite 事务快照。
- 累计按 UTC 日期、会话、项目、模型、供应商及实际账号/域名保存。最近请求明细单独保留最近 5000 条，设置页继续展示其中最新 50 条。
- 输入、输出、缓存读取和缓存写入分别存储，不将汇总行数当成请求数，也不把汇总 token 再乘请求数。设置总览原先漏掉缓存写入，本次补齐“输入（含缓存）”及命中率分母；服务商卡仍按原有不含缓存输入展示。
- 完成消息和会话标识生成 SHA-256 去重标识，消息正文不落入用量存储。清理明细不清理去重收据，因此较晚的重复回包不会增加累计。
- 去重收据只存摘要，按请求数缓慢增长；累计行按日期与分组增长。此设计减少明细存储，不宣称数据库大小永久固定。

## 升级及故障处理

- 首次成功事务导入 `usage/usage.jsonl` 中仍存在的有效记录。原文件完整保留，不再追加或裁剪；没有账号字段的旧记录保持原分组，不猜测归属。
- 无标识的两条完全相同旧行仍视为两次请求。迁移标记与累计一同提交，中断后可重试，不重复计数。
- 坏行留在原文件，两个入口提示可能不完整；整个文件不可读时不标记迁移成功。
- 每条新用量先原子保存为待入账文件，再由 SQLite 事务写入去重收据、累计和明细。数据库失败时保留已落盘的待入账记录，后续读写重试；提交成功但来不及删除文件时，由收据防重复。
- 跨进程文件锁协调多个 worker 和 App 的迁移、写入、读取及清空。数据库损坏或版本过新时不替换为空库，页面读取失败保留已有数字并报错。
- 「清空记录」是显式重置：清空累计和近期明细，保留导入标记与不可逆去重摘要，防止旧文件和旧回包让数字复活。导入原件仍保留，确认框明示此事。
- 已裁掉的历史不自动恢复；本次不扫描会话日志，不承诺供应商最终账单与接口报告 token 完全一致。升级时应让旧版 worker 退出，避免旧进程继续往只导入一次的 JSONL 写入。

## 已执行的本机检查

`python3 Scripts/test-usage-ledger-sql.py` 直接提取实现中的 SQL，在项目内临时数据库运行七组测试：

1. 10020 次请求保留 5000 条明细，累计和旧模型仍保留；重复旧回包不增加累计。
2. 事务中途失败后收据、累计及明细一起回滚。
3. 清空保留去重和迁移标记，旧请求不复活，新请求仍能记录。
4. 账号、域名、会话、日期与旧记录身份分离；零明细仍保留累计。
5. 多连接并发事务无丢失、无重复。
6. 关闭数据库再打开，累计及去重仍存在。
7. 整数溢出不将累计悄悄转成浮点数；整次请求回滚。

此测试验证真实 SQL，不执行 Swift 迁移、文件锁和页面逻辑，不能代替下列测试。

## 尚需 Xcode 环境执行

在 `Packages/ApelinKit` 执行：

```sh
swift test --filter UsageLedgerTests
swift test --filter UsageRecorderTests
swift test --filter UsageProviderSummaryTests
```

新增 16 项 Swift 测试覆盖：明细清理保累计、清理后的重复回包、账号/会话隔离、旧行导入及坏行保留、非 UTF-8 原件、事务失败待入账恢复、提交后待入账重放、并发写入、跨日零明细、损坏库保留、稳定消息摘要，以及坏待入账不得假成功、清空后坏待入账不得复活、跨列累计溢出、单列溢出后仍可清空，以及未导入坏原件可显式重置。

随后在仓库根执行 `make check` 和完整 App/worker 构建。当前设备缺少 xcodebuild，只有 Swift 5.7.2 前端；兼容副本语法解析不等于类型检查，完整门禁仍未通过。

## 尚需新包真机验收

- 设置及会话入口：核对同一份数据的累计、模型、账号及最大会话排行；切换页面后数字一致。
- 清理及恢复：在测试数据目录导入超过 5000 条记录，重启后累计不减，旧模型仍在，近期明细限量。
- 迁移：用副本验证原文件不变、坏行提示可见、再次打开不重复计数。
- 并发及失败：两个会话同时完成请求；模拟数据库写入失败后恢复，验证待入账只计一次。
- 清空：仅在测试数据上确认重置后重启仍为空，旧完成消息重放不复活，新请求能继续累计。
- 界面：检查新增说明换行、错误提示、清空确认文案及系统旁白；不要在日常统计数据上做破坏性验收。
