# 在 Xcode 中继续开发

从内置模板新建的项目会附带原生 `.xcodeproj`、共享 Scheme 和 Workspace，便于在 Mac 上继续编辑。已有项目不会自动补建工程，已有 `.xcodeproj` 也不会被覆盖。

## 传到 Mac

可通过 Git 同步项目，或在项目导出菜单选择：

- **专用项目文件**：供应用导入，保留项目及其 Git 历史。
- **源码 ZIP**：可由普通解压工具打开，保留源码、资源、授权文件和已有 Xcode 工程；不包含应用专用的项目元数据、Git 历史及设备构建记录，并遵守项目的忽略规则。

源码 ZIP 解压到项目名称对应的顶层文件夹。文件保留可执行位，符号链接不随归档传出。

## 编辑与构建

在 Mac 打开 `.xcodeproj`，选择相应 Scheme。工程包括创建时已有的源码和资源，`Xcode/Support/` 保存复制的开发头文件与链接桩，例如 `substrate.h` 和 `libsubstrate.tbd`，Mac 无需读取设备上的扩展目录。

工程仅在创建时生成，此后由 Xcode 管理。在设备上新增文件或调整产物后，需要在 Xcode 中同步调整；不会再次生成工程以覆盖手工设置。

## 兼容性与限制

- 支持 Objective-C、C、C++ 和 Swift 源码对应的原生目标；Mac 需要相应版本的 Xcode 和 iPhoneOS SDK。
- 模拟器与设备使用独立的平台产物，模拟器配置为 ad-hoc 签名，无需开发者证书。越狱专用框架、链接桩及接口不保证能在模拟器运行。
- 设备目标默认输出未签名二进制；`.deb` 安装布局、`.ipa` 打包、`ldid` 签名及越狱权限仍需单独处理。
- 随项目提供的 Swift 模块源码没有自动生成的模块目标，需要在 Mac 上手动配置。
- 较早创建的应用或设置面板若缺少执行文件名，需要在其 `Info.plist` 中添加 `CFBundleExecutable`，值为产物自身的名称。新模板已包含该项。
