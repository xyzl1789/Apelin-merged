Apelin 0.4.10 让每个项目可以有自己的指令、可以在设置里直接从 GitHub 导入技能，工具链补齐了 `otool` 和 `ar`，并放宽了项目的 iOS 版本下限。

- 技能只能从「文件」一个文件夹或一个 Markdown 文件地导入，想在 GitHub 上分享的技能得先下载下来。现在在 设置 ▸ 代理 ▸ 技能 ▸ + ▸ 从 GitHub… 粘贴一个公开仓库、仓库里的文件夹或单个 `SKILL.md` 的链接，即可看到 Apelin 找到的技能、逐个预览、勾选要的并连同参考文件一起导入。仓库里的东西不会运行；聊天用不了的技能会写明原因、不能勾选；遇到同名技能会先询问。
- 如果技能文件夹里某个 `SKILL.md` 以空的头部开始（一行 `---` 紧接另一行 `---`），所有聊天都起不来，设置 ▸ 代理 ▸ 技能也打不开。现在导入这样的文件会被拒绝，已经在文件夹里的会在技能页标为问题，其余技能与聊天照常工作。
- 在所有工具链上，`otool` 会报找不到 `otool-classic`，带 `s` 的 `ar rcs` 会报 ranlib 失败，于是你或代理都无法查看二进制、也无法用它建静态库。本版本新设置的工具链自带这两样。先前设置好的工具链照常构建，并会在 设置 ▸ 工具链 里它的名字下提示「来自更早的设置。重新设置即可补上 otool 与 ar。」要得到它们，在 设置 ▸ 工具链 ▸ + 里把该版本再设置一次，它会以另一个 ID 出现在旁边，把项目切过去、确认没人用旧的后再移除；在那之前可以用 `libtool -static -o` 建归档。
- 代理确认一个 tweak 是否加载时只监听 15 秒（重启则为 30 秒），对按需启动的进程（例如连上 Mac 才启动的守护进程、你手动打开的 App）无法确认，点停止也取消不了检查，加载失败与进程从未启动也分不开。现在代理会先告诉你该启动什么，最多监听 3 分钟，听到标记就立刻结束，点停止立即取消，并报告目标进程在这次检查期间是否运行过，或者本来就在运行、需要重启。
- Apelin 创建的每个项目都要求 iOS 16.0，包里的 `firmware (>= 16.0)` 也写死，导致一个其实能在 iOS 15 上运行的 tweak 或命令行工具装不上去，除非手动改包的 `control`。现在 C 或 Objective-C 项目可以把部署目标降到 `15.0`（在 `apelin-project.json` 里改，或让代理改），包里的 `firmware` 相应变为 `>= 15.0`。新项目仍从 16.0 开始，Apelin 自身仍要求 16.0，Swift 项目也仍要求 16.0。
- 代理新建项目并为它开一个对话时，那个对话有时会开在当前聊天所属的项目里；代理写的反馈或议题因含隐私数据被拒时，错误只说什么像设备标识，代理不知道该删哪句。现在代理按项目名指定新项目，并回答对话开在哪个项目；隐私拒绝会引用匹配到的内容和位置（例如完整的 40 位提交哈希也像设备标识，提交请用前 7 到 12 位）。
- 代理写 GitHub Actions 工作流或查看一次失败的运行时，工作流常因脚本没有可执行权限、YAML 里没加引号的冒号、macOS runner 上的分片未签名而在第一次推送就失败，而没有管理员权限又读不到失败日志。现在代理会写好可执行的脚本、给带冒号的 YAML 值加引号、为 macOS runner 上的每个分片签名，并直接在对话里读出失败运行的步骤和错误信息。
- 想给代理一段长期偏好，只能在每个聊天里重复，或者给每个项目各放一份 `AGENTS.md`。现在一个项目可以有自己的指令：在某个项目聊天的 More 菜单 ▸ Project ▸ Project Instructions… 里编辑，它会排在所有聊天共用的指令之后，同一条对话在下一条消息就用上，删除项目时一并清除。共用那份仍在 设置 ▸ 代理 ▸ Prompt Injection。

Requires iOS 或 iPadOS 16.0 或更高、A12 芯片或更新、Irisin 4.7.3 或更新、icli 0.11.0 或更新。RootHide 选 `iphoneos-arm64e` 包，rootless 选 `iphoneos-arm64` 包，并逐一对照 `SHA256SUMS` 校验下载。
